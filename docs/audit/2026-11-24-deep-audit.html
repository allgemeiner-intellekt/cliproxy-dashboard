一句话结论

产品思路扎实，几个核心模块（配置编辑器的 diff 与并发控制、额度错误处理、金额用整数微美元存储）做得很用心。问题集中在三处：

  • “边角状态”几乎没设计。加载中、出错、重复点击、离开前未保存，这几种情况在大多数页面都没处理。你从界面上感觉到的“不成熟”，大部分来自这里，而不是视觉风格。
  • 完整版的安全模型只靠“绑定 127.0.0.1”。它挡不住 DNS 重绑定，而管理桥连账号的 OAuth 凭据文件都允许下载。
  • 你这个 fork 的“只读试用版”是靠改写入口实现的。这导致约 7k 行死代码、文档和部署配置全部失配，而且它其实并不只读：它仍在消费代理那条只能有一个消费者的用量队列。

专题

1. 界面状态覆盖：你感觉“不成熟”的主要来源

每个页面在 5 种非理想状态下的表现。✓ 处理得当，◐ 部分处理，✗ 没处理或处理错误。

修法是同一套：一个共享的 useAsync / usePoll 钩子统一管理加载、错误、重试和请求顺序，加上 ConfirmDialog 的 busy 属性和一个常驻的错误提示组件。做一次，6 个页面一起受益。

2. 文字对比度

下面的示例文字就是项目里的真实颜色，画在真实的卡片底色 oklch(0.172 0 0) 上。竖线是 WCAG AA 正文门槛 4.5:1。--fg-3 用在 11–12px 的眉标、图表刻度、空状态和表格占比列上，而这些恰恰是最小号的字。

单位 KiB（未压缩）。完整版只有一个 chunk，Vite 会提示“超过 500 kB”。CodeMirror、Lezer 和 yaml 加起来占一半以上，但只有配置页用得到。

建议路线

做得好的地方

  • 配置编辑器：表单 / YAML 双视图，保存前看 diff，用 If-Match sha256 做乐观并发，每次写入前备份（权限 600，保留 50 份），并且锁住了 server/port 字段，防止把自己锁在门外。
  • 额度错误处理：errors.ts 把失败翻译成标题加提示，遵守 Retry-After 和 429 退避，旧读数保留并标为“过期”，用 localStorage 缓存让首屏秒开。
  • 危险操作统一用原生 <dialog> 确认，自带焦点陷阱和 Esc。删除最后一个 key 会被拦下。
  • 自定义控件的 ARIA 做得不错：switch、aria-pressed、quota 条用 role="meter"、导航用 aria-current。
  • 金额用整数微美元存储，未知价格存 NULL；插入幂等（稳定 id + onConflictDoNothing）；重新计价和导入都在事务里。
  • 管理写操作的白名单很严：精确匹配 key 集合，屏蔽“全部删除”的变体；配置写入串行化。
  • 共享池 token 有 192 位熵、只存哈希；历史推送的路径校验到位；YAML 别名展开有深度和大小上限。
  • 依赖克制：没有 UI 库和图表库，SVG 图表手写；前后端 TypeScript 都没有一个 any；所有定时器和监听器都正确清理。
